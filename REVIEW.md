### Also note anything you looked at and decided was **not** a defect, and why:

1. **`doc.pop("_id", None)` in responses:**
   - MongoDB internal `_id` is an `ObjectId`. The OpenAPI contract states that `_id` is internal and must never appear in API requests or responses. Removing `_id` from the return dictionary is intended and correct.
2. **Initial derived field values on punch-in (`punch_out: None`, `work_hours: None`, `overtime_minutes: 0`, `half_day: False`, `history: []`):**
   - OpenAPI specifications and `DATA_MODEL.md` explicitly confirm that punch-out fields remain `null`/default upon punch-in, and `history` only tracks manual regularizations (`PATCH`), never initial punch events.
3. **Calendar date string comparisons in MongoDB (`$gte` and `$lte` on `"YYYY-MM-DD"`):**
   - ISO 8601 calendar date strings `"YYYY-MM-DD"` sort lexicographically identically to chronological date order. Querying with `$gte` and `$lte` on string fields in MongoDB works properly and avoids timezone distortion.
4. **Using `count_documents(q)` instead of `estimated_document_count()`:**
   - Although `estimated_document_count()` is faster for unindexed whole-collection counts, `openapi.yaml` (Rule R10) requires `total` to strictly reflect applied query filters. `count_documents(q)` is required and correct when backed by appropriate indexes.
